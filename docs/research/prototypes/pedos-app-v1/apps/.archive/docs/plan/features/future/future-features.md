# Future Features

This doc is the lightweight backlog for features that are intentionally out of the current MVP scope.

Use it when a feature should stay captured, but should not live in the active MVP planning queue.

## Not In MVP

The items in this doc are not part of the current MVP handoff.

They can be revisited later once the core iPhone recording app is stable.

## Backlog

| Feature | Why Later | Rough Timing | Related Issue | Notes |
|---|---|---|---|---|
| History and playback expansion | Not needed as a standalone MVP planning pass right now | Later | [#8](https://github.com/serpcompany/pedos-app/issues/8) | richer saved-recording browsing, clearer playback management, inline vs detail playback decision, empty/loading/populated history states, delete flow, playback failure behavior |
| Stats dashboard | Not planned for the current MVP | Later | [#9](https://github.com/serpcompany/pedos-app/issues/9) | simple stats payoff area, total count, total duration, recent activity summary, empty/populated states, later calendar or heatmap expansion |
| Friends | Social features are out of current MVP scope | Later | TBD | add friends inside the app, manage friend connections, create a social graph for sharing and collaboration |
| Share fart recordings with friends | Requires friend relationships, permissions, and sharing UX beyond MVP | Later | TBD | let users send or expose saved fart recordings to friends inside the app |
| Fart song collabs | Depends on friends, cross-user permissions, and multi-user source selection | Later | TBD | combine some of your recordings with a friend's recordings to generate AI songs together |
| Social profile page | Requires a social posting model and engagement system beyond MVP | Later | TBD | profile page similar to a lightweight social feed with fart posts, likes, comments, votes, and visible user identity |
