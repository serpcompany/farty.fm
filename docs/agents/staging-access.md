# Staging access

The password gate in front of Staging, how local runs pass it, and the Fixture Library only Staging carries. Environments and deploys are in [the web app guide](web.md).

- **Staging asks for a password.** The password is `stagingpassword`, with any username. It's public, so it's the plain variable `STAGING_BASIC_AUTH_PASSWORD` in `env.staging`, not a secret. The Worker entry (`apps/web/worker.ts`; the gate is `src/lib/staging-access.ts`) checks it after the host redirects and before anything is served, then strips `Authorization`. Staging sets `assets.run_worker_first`, so static files need it too. Only `/robots.txt`, Stripe's webhook (`POST /api/stripe/webhook/`, which checks Stripe's signature instead) and requests with the `x-farty-smoke-test` header and no `Authorization` skip it. The Fixture Library under `/fixtures/` needs the password even with that header. Every response keeps `X-Robots-Tag: noindex` unless its request passed the password. Outside Production a missing variable refuses everything. Production has no gate.
- **Local runs pass the gate.** Copy `apps/web/.dev.vars.example` to `.dev.vars` (git-ignored). Local workerd runs (`opennextjs-cloudflare preview` with no `--env`) gate pages with it, and `E2E_SERVER=preview pnpm test:e2e` sends it with Playwright's `httpCredentials`, on `E2E_PORT`. `pnpm dev` has no gate. CI's `e2e` job writes `.dev.vars` the same way.
- **Only Staging carries the Fixture Library.** `build:staging` copies it to `public/fixtures/recordings/` and sets `NEXT_PUBLIC_FIXTURE_LIBRARY=1`, which shows its loader on Profile. `build:production` removes it, then `scripts/fixture-library.ts check` fails the build if it carries any file under a `fixtures/` path, any file identical to one in `fixtures/recordings/`, or the loader's text.
