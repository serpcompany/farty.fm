# Web app gotchas

What the web app taught its builders, kept so the next change doesn't relearn it.

## Learned in slice 1

- `apps/web` isn't `"type": "module"`, so Playwright compiles `e2e/` as CommonJS. Use `__dirname`, not `import.meta`.
- Biome treats any function named `use…` as a React hook. That's why the fake-microphone helper is `withFartingMicrophone`.
- Accounts in the journeys (#155): a guest's Toots last only the visit (their Recordings are kept: owner, 2026-10-25, #203), so a spec whose Toots outlast a relaunch signs in first (`signInByApi` in `e2e/account.ts`, with the code from `/dev/mail/`). Locally every request comes from 127.0.0.1, one client with 10 codes in 10 minutes, so `ownClient` gives each test its own `cf-connecting-ip`, which Miniflare passes through. `skipWelcome` and `recordAndSave` (`e2e/record.ts`) keep the account step out of the way unless a spec asks for it.
- Re-recorded through Chromium's fake audio device in slice 1, 4 of 5 Melodic fixtures gave a Recording Pitch identical to golden. 094 (low confidence) came out 20 cents high, still B3. Expect small differences on re-recorded audio. Assert note names, not exact MIDI.
- V8's `2 ** x` and `Math.log2` differ from numpy by an ulp on some pYIN bins. `analysis/numeric.ts` has correctly rounded `exp2` and `log2`. Use them, or bit-identity breaks.
- `next dev` adds a trailing slash to every path (`trailingSlash: true`), and Better Auth's routes have none, so `auth-request.ts` forwards each sign-in request without it.
- Safari mutes Web Audio when the silent switch is on unless `navigator.audioSession.type = 'playback'` is set (`context.ts`). The microphone needs `'play-and-record'` while it's open, which is from the first time Record shows to the end of the launch (`keepMicrophoneOpen`), so sounds play in it then too (`setPlaybackSession`).
- Farty's icons use `next/image` with `unoptimized`, because Workers has no image optimizer.
- 16-bit WAV: encode as `round(x × 32768)`, clamped, and decode as `/32768`, as other decoders do.
- A page prerendered by `generateStaticParams` is served on Workers from the static-assets incremental cache (`open-next.config.ts`), which `opennextjs-cloudflare preview` and `deploy` fill. Without it, such a page 404s on Workers though `next build` lists it. `/compose/[song]/` is prerendered with `dynamicParams = false`, so the service worker can keep each Song's page (`/shell.json`), and an unknown Song 404s.
- Both Web Workers load one Turbopack script, each with its own chunks in the URL's fragment (`#params=`), and a worker runs what its script's response URL says. The service worker keeps a copy with no URL, or a worker started offline runs the other worker's chunks.
- Playwright's `evaluate` counts as a tap, and Chromium gives every page Playwright loads the activation of one. To test a page that was never tapped, override `UserActivation.prototype.hasBeenActive` in an init script, as `song-creator.spec.ts` does.
- `decodeAudioData` detaches the `ArrayBuffer` it's given. Pass it a copy (`wav.slice(0)`) of audio you still need, as Song Creator does with a Toot it hasn't saved.
- `cloudflare-env.d.ts` types the bindings for `getCloudflareContext()`. Regenerate it with `pnpm cf-typegen` after any change to bindings or vars; `pnpm typecheck` fails while it's out of date. It declares the Workers runtime's globals over the DOM's, so browser code sometimes needs the DOM's own form, such as `window.addEventListener` or `appendChild`.

## The browser, from `src/lib`

- **One AudioContext.** iPhone Safari allows only a few, so `audio/context.ts` makes one and keeps it. It starts only in a tap: Record, Play, or `startAudioInTap` for a screen that plays after an await, such as Song Creator.
- **The microphone's grant on iPhone Safari (#222).** A page's grant lasts 24 hours while capture runs. Once capture stops, and a muted track counts, a `getUserMedia` outside a tap asks again after 1 minute, and any call after 10. So `keepMicrophoneOpen` opens without a tap only within 50 s of capture stopping (`microphone-grant.ts`), or when the browser keeps the grant itself, as Safari's per-site setting at Allow does. `navigator.permissions` also says `granted` while the page's own grant lasts, so only an answer from before the page was granted counts as the browser's.
- **Interruptions.** On iPhone, Siri, an alarm, a call banner or hiding the page mutes the track or stops the context without ending it. The capture processor's pre-roll is flushed, and capture goes on with the same stream once the track unmutes and a tap starts the context. A stream kept through an interruption can come back sending exact zeros (#172, #222), so its first take opens a fresh stream in the same tap. A call or another app ends the track, and the take with it. iPhone Safari mutes a hidden page's stream, so it's kept; a browser that keeps listening while hidden has it released after 1 s, since iPhone may unmute it just before it says the page shows. A computer's product page releases it (#199).
- **The capture processor** is an AudioWorklet loaded from a Blob URL of its source (`capture-processor.ts`), so a busy page can't drop samples. It keeps the last 0.3 s in a ring, which each take starts with, and sends a first batch in the first render quantum after `start`, so the page knows capture began. Its node must reach the destination to be pulled, through a gain of 0 that keeps the microphone off the speaker, and `close` makes `process` return false so the audio thread frees it.
- **IndexedDB.** The `pedos` database is at version 3: version 1 held Recordings, 2 added Toots, and 3 the outbox, downloads and meta. Upgrading to 3 queues every kept Recording and Toot to upload. An older version open in another tab holds the upgrade until it closes (`onWaitingForOtherTabs`), and a later version opening elsewhere makes this tab close its connection. WebKit can drop the connection while a tab sleeps (#222), as `InvalidStateError` or "Connection to Indexed Database server lost": `withDb` runs the work once more on a fresh connection, and since the first run may have committed unheard, a retried save looks for its own write first (`holds`). A transaction names `outbox` before its first request: asking for a store after a request aborted the transaction throws, and leaves the requests already made, and `tx.done`, unhandled.
- **Tabs.** A sync runs under the Web Lock `pedos-sync`, so a browser's tabs take turns, and tells the other tabs what changed on the `pedos-library` BroadcastChannel. Each open tab holds `pedos-open`, shared, so a new tab never clears another tab's Toots.
- **Timeouts.** Vitest's fake timers don't drive `AbortSignal.timeout`, so requests time out through `withinTimeout` (`timeout.ts`), a `setTimeout` the tests can run.
- **Stale builds (#222).** A tab opened before a deploy later loads scripts the server no longer has. Next.js 16 loads a navigation from another build in full, and Turbopack retries a failed chunk once; after that, `stale-build.ts` reloads the page once nothing unsaved is on screen (`holdReload`), at most once in 10 minutes a tab, and never with sessionStorage blocked. A failed `import()` is a `TypeError`: "Importing a module script failed." in WebKit, "Failed to fetch dynamically imported module" in Chromium. A worker fires a plain `error` event when its own script fails, and an `ErrorEvent` when an `importScripts` fails: "NetworkError: Load failed" in WebKit, "Failed to execute 'importScripts'" in Chromium.
- **Installing.** iPadOS Safari says it's a Mac and Chrome on an Android tablet says Linux; only touch gives them away (`install.ts`). An in-app browser built on SFSafariViewController sends Safari's exact user agent, so it can't be told apart. The service worker registers only in a build: on `next dev` it would outlive the session on a localhost port other apps share.

## The screens and routes

- The root layout's inline script sets `data-welcomed` on `<html>` from `localStorage` before paint, so a touch tablet shows a returning visitor the app and a new one the lander (the `unwelcomed` variant in `globals.css`) with no flash. A computer (the `desktop` variant: 768px and wider, with a mouse or trackpad) gets the lander on every tab by CSS alone.
- The manifest is a route handler, not `manifest.ts`, so the layout can link it with `crossorigin="use-credentials"`. Chrome fetches a manifest without credentials, which behind the Staging password gets a 401, and Next adds the attribute itself only on Vercel previews.
- The home page writes its own canonical, the bare origin, because Next adds a trailing slash to the layout's. The 404 page has none, since the layout's would name the missing URL.
- The shell picks the current tab from `useSelectedLayoutSegments()`, not `usePathname()`. The 404 page is prerendered once, as `/_not-found`, and served at every missing address, so the server draws it with no tab while `usePathname()` in the browser reads the address. Under a tab (`/compose/not-a-song/`) that drew Compose as current and broke hydration (React error #418). The segments come from the route tree sent with the page, which says `/_not-found` on both sides.
- Every Toot opens on one static page, `/toots/toot/?id=`, because a Toot's id is made on the device. The service worker keeps it and each Song's page from `/shell.json`.
- Song Creator plays the Toot once it's made, and only a tap starts audio: the taps that open it call `startAudioInTap`, and one opened from a link or a reload waits for a tap (`navigator.userActivation`).
- Back from Song Creator or a Toot's screen goes back in history when Compose or Toots opened it, and otherwise replaces the page, so the system Back never opens it again (`back-link.tsx`).
- Done or Try it on a Result keeps the record flow open until the next page shows. Closed first, it would show the Record screen idle on the way, which opens the microphone.
- The note view takes a tap anywhere and plays the nearest note. Each note is also a button, out of the pointer's way, for the keyboard and screen readers.
- Back from Checkout, Song Creator makes the same Toot again, with the id it was paid for (ADR 0010), and waits for a tap to play it.
- The lander's screenshots are a `<picture>` whose source applies from 768px and whose `<img>` is a transparent pixel, loaded lazily, so a phone, or a lander hidden once Farty is open, downloads none of them. Download App's QR code is drawn on the server at build (`download-qr.tsx`), so no QR library reaches the browser, black on white in both themes, as scanners expect.
- The install prompt shows once, after the first saved Recording, and waits for the record flow to close. It also registers the service worker, and asks the browser to keep Farty's storage once there's a Recording (#203), as signing in does.
- The account step comes back after a reload while it was open (a phone dropping the tab during Mail), and asks a browser whose session ended to sign in again, once a visit.
- Leaving the Toots tab lets go of the audio its rows decoded. A Toot that plays keeps playing into its screen, as on the iPhone; another tab stops it.
- Profile's Safari tip (Page Menu, Website Settings, Microphone: Allow) follows Apple's "Browse the web privately in Safari on iPhone" (iOS 27).
- `--brand` is the app icon's pink, for accents. `--brand-strong`, a deeper shade, goes behind white text, where it keeps a 5:1 contrast.
- `error.tsx` and `global-error.tsx` report what broke a screen as `uncaught-error` and offer a reload. Next passes only what its built-in boundary catches to `window.reportError`, which `installErrorReporting` hears; an error these catch, Next only logs, so they report it themselves. `global-error.tsx` replaces the root layout, so it brings its own `<html>`, styles and viewport.

## The journeys

- Every spec imports `test` and `expect` from `e2e/test.ts`, which fails a test on any console error or page error. A test that causes one on purpose (an aborted route, offline, a 404, the synthetic crash) names it with `pageErrors.expect(...)`. A second browser comes from the `newContext` fixture, and a persistent profile is watched with `pageErrors.watch(context)`. A context's init script also runs in each new page's `about:blank`, whose opaque origin has no `localStorage`, `navigator.storage` or `navigator.mediaDevices`, so the init scripts that use them skip a document without an origin.
- No test waits a fixed time, and none is retried (`retries: 0`). A check that something doesn't happen waits for the step that would have done it: the page running its pending work, the effect that would act included (`pageSettled`, a background-priority task: `requestIdleCallback` starves on a busy machine), the page clock run past the app's timer (`record-grant.spec.ts`), what the app does instead (the capture processor loading, Save disabled while the visit opens), or an event (a worker's `error`, with the Navigation API's `navigate` events to catch a reload). The fake microphone holds a press until its own audio clock has played the fart for 150 ms, and a take until the app has captured 1.3 s past the fart.
- A failed journey keeps its trace (screenshots and DOM snapshots at each step) and a screenshot, not a video. Recording video for every test, to keep only the failures', slowed teardown past the 30 s test timeout on a loaded machine. A journey that must fit inside one of the app's own timeouts, such as the 5 s session read, gives the fake microphone `answersAfterMs: 0` instead of the 800 ms the "Starting…" journeys need.
- axe can't tell the background of text over a gradient drawn by a sibling layer, as on the product page's hero. It marks that text as needing review (`bgOverlap`), not as a violation, so `e2e/accessibility.ts` measures it: it screenshots the text, then the same box with every text colour transparent, and checks the contrast only at the pixels the text changed. It reads every text colour and takes every first screenshot before hiding any text, because a button's colour transition leaves its computed colour transparent for a moment after the hiding style is removed.
- Journeys record through a fake microphone in the page (`e2e/fake-microphone.ts`), never Chromium's file device. That device (`--use-file-for-fake-audio-capture`) plays the file from when the microphone opens, not from the tap, so on a busy machine a take that started late missed the whole fart. `withFartingMicrophone` (`e2e/record.ts`) sets `e2e/test.ts`'s `fakeMicrophone` option, which adds the microphone to the test's context and to each `newContext`, and grants it, so Record opens it as it shows. A journey about the first tap or the grant passes `granted: false` (#149). The microphone plays a fixture (090 is G3, 084 two farts, 065 Noise-like) as Record is pressed (`fartAndRecord`), after `waitForOpenMicrophone` has seen the app's capture processor, not just getUserMedia (#172).
- A Song opened by a tap plays by itself once its Toot is made, Try again included (#234). Song Creator shows Ready or Playing in the same render that makes the Toot, so a page that shows Ready never started a play.
- A relaunched or second profile's service worker answers navigations without the Staging gate's credentials, so the Toots, sync and Song Creator journeys block service workers, except in their offline tests.
- Chromium can't emulate `display-mode`, so `profile.spec.ts` answers `matchMedia` itself, and fires `beforeinstallprompt` only for an installable site it trusts, so `e2e/install-prompt.ts` fires it as Farty listens. WebKit drops a `navigator.mediaDevices` wrapper nothing holds, so the fake microphone holds it. `next dev` puts its Dev Tools button over the Recordings tab at phone size, so `tabs.spec.ts` hides it.
- The fixtures behind the counts: the whole Fixture Library unlocks 8 of the 12 Songs, as Jingle Bells, Row, Row, Row Your Boat, Amazing Grace and Auld Lang Syne each have a note longer than any fixture near its pitch (ADR 0011, ADR 0012). Mary Had a Little Lamb unlocks with 095 (F2), 017 (D♯2), 022 (E2) and 002 (A♯2), the reference's `melody_fit()` picks, and needs 002, the only fixture whose fart (1.80 s) outlasts its last note (1.40 s). In the Library, 002 is Recording 1: a 1.799 s fart in a 4.2 s take (#227). A re-recorded take keeps its Recording Pitch, but its settle time depends on where the fart falls in the take (095: 6 to 29 ms, against golden's 29), and so do the notes a Song needs after that one fart, so `compose.spec.ts` checks their shape there, not golden's notes.

## Shell gotchas

- Where zsh has `noclobber` set, as on the macOS machine, overwrite a file with `>|`, and use `bash -c` for `set -- $words` loops.
- To call `gh.sh` through a variable, keep only its path in it: `G=~/.claude/skills/serp-github-app/scripts/gh.sh; bash $G pr view <n>`. zsh doesn't word-split `$G`, so `G="bash <path>"; $G ...` fails: zsh looks for one command named `bash <path>`. Writing the whole `bash ~/.claude/skills/serp-github-app/scripts/gh.sh ...` call, as this page does, works too.
