# Web app gotchas

What the web app taught its builders, kept so the next change doesn't relearn it.

## Learned in slice 1

- `apps/web` isn't `"type": "module"`, so Playwright compiles `e2e/` as CommonJS. Use `__dirname`, not `import.meta`.
- Biome treats any function named `use…` as a React hook. That's why the fake-microphone helper is `withFakeMicrophone`.
- Chromium's fake microphone: `--use-file-for-fake-audio-capture=<wav>%noloop` plays the file once. It needs a PCM WAV. Fixtures 090 (G3), 084 (G♯3, two farts) and 065 (Noise-like) are the e2e cases. It plays from the moment the stream opens, before the app captures, so a take loses the file's first tens of ms (60 ms on CI). That cost 094, which is loud from 8 ms, its steady note (#141). A spec whose farts must start whole uses `e2e/fake-microphone.ts`, which plays each fart as Record is pressed, and `waitForOpenMicrophone`, which waits for the app's capture processor rather than getUserMedia (#172).
- Accounts in the journeys (#155): a guest's Toots last only the visit (their Recordings are kept: owner, 2026-10-25, #203), so a spec whose Toots outlast a relaunch signs in first (`signInByApi` in `e2e/account.ts`, with the code from `/dev/mail/`). Locally every request comes from 127.0.0.1, one client with 10 codes in 10 minutes, so `ownClient` gives each test its own `cf-connecting-ip`, which Miniflare passes through. `skipWelcome` and `recordAndSave` (`e2e/record.ts`) keep the account step out of the way unless a spec asks for it.
- Through the fake microphone, 4 of 5 Melodic fixtures give a Recording Pitch identical to golden. 094 (low confidence) comes out 20 cents high, still B3. Expect small differences on re-recorded audio. Assert note names, not exact MIDI.
- V8's `2 ** x` and `Math.log2` differ from numpy by an ulp on some pYIN bins. `analysis/numeric.ts` has correctly rounded `exp2` and `log2`. Use them, or bit-identity breaks.
- Safari mutes Web Audio when the silent switch is on unless `navigator.audioSession.type = 'playback'` is set (`context.ts`). The microphone needs `'play-and-record'` while it's open, which is from the first time Record shows to the end of the launch (`keepMicrophoneOpen`), so sounds play in it then too (`setPlaybackSession`).
- The Welcome icon uses `next/image` with `unoptimized`, because Workers has no image optimizer.
- 16-bit WAV: encode as `round(x × 32768)`, clamped, and decode as `/32768`, as other decoders do.
- A page prerendered by `generateStaticParams` is served on Workers from the static-assets incremental cache (`open-next.config.ts`), which `opennextjs-cloudflare preview` and `deploy` fill. Without it, such a page 404s on Workers though `next build` lists it. `/compose/[song]/` is prerendered with `dynamicParams = false`, so the service worker can keep each Song's page (`/shell.json`), and an unknown Song 404s.
- Both Web Workers load one Turbopack script, each with its own chunks in the URL's fragment (`#params=`), and a worker runs what its script's response URL says. The service worker keeps a copy with no URL, or a worker started offline runs the other worker's chunks.
- Playwright's `evaluate` counts as a tap, and Chromium gives every page Playwright loads the activation of one. To test a page that was never tapped, override `UserActivation.prototype.hasBeenActive` in an init script, as `song-creator.spec.ts` does.
- `decodeAudioData` detaches the `ArrayBuffer` it's given. Pass it a copy (`wav.slice(0)`) of audio you still need, as Song Creator does with a Toot it hasn't saved.
- `cloudflare-env.d.ts` types the bindings for `getCloudflareContext()`. Regenerate it with `pnpm cf-typegen` after any change to bindings or vars; `pnpm typecheck` fails while it's out of date. It declares the Workers runtime's globals over the DOM's, so browser code sometimes needs the DOM's own form, such as `window.addEventListener` or `appendChild`.

## The browser, from `src/lib`

- **One AudioContext.** iPhone Safari allows only a few, so `audio/context.ts` makes one and keeps it. It starts only in a tap: Record, Play, or `startAudioInTap` for a screen that plays after an await, such as Song Creator.
- **The microphone's grant on iPhone Safari (#222).** A page's grant lasts 24 hours while capture runs. Once capture stops, and a muted track counts, a `getUserMedia` outside a tap asks again after 1 minute, and any call after 10. So `keepMicrophoneOpen` opens without a tap only within 50 s of capture stopping (`microphone-grant.ts`), or when the browser keeps the grant itself, as Safari's per-site setting at Allow does. `navigator.permissions` also says `granted` while the page's own grant lasts, so only an answer from before the page was granted counts as the browser's.
- **Interruptions.** On iPhone, Siri, an alarm, a call banner or hiding the page mutes the track or stops the context without ending it. The capture processor's pre-roll is flushed, and capture goes on with the same stream once the track unmutes and a tap starts the context. A stream kept through an interruption can come back sending exact zeros (#172, #222), so its first take opens a fresh stream in the same tap. A call or another app ends the track, and the take with it. iPhone Safari mutes a hidden page's stream, so it's kept; a browser that keeps listening while hidden has it released after 1 s, since iPhone may unmute it just before it says the page shows. A computer's product page releases it (#199).
- **The capture processor** is an AudioWorklet loaded from a Blob URL of its source (`capture-processor.ts`), so a busy page can't drop samples. It keeps the last 0.3 s in a ring, which each take starts with, and sends a first batch in the first render quantum after `start`, so the page knows capture began. Its node must reach the destination to be pulled, through a gain of 0 that keeps the microphone off the speaker, and `close` makes `process` return false so the audio thread frees it.
- **IndexedDB.** The `pedos` database is at version 3: version 1 held Recordings, 2 added Toots, and 3 the outbox, downloads and meta. Upgrading to 3 queues every kept Recording and Toot to upload. An older version open in another tab holds the upgrade until it closes (`onWaitingForOtherTabs`), and a later version opening elsewhere makes this tab close its connection. WebKit can drop the connection while a tab sleeps (#222), as `InvalidStateError` or "Connection to Indexed Database server lost": `withDb` runs the work once more on a fresh connection, and since the first run may have committed unheard, a retried save looks for its own write first (`holds`). A transaction names `outbox` before its first request: asking for a store after a request aborted the transaction throws, and leaves the requests already made, and `tx.done`, unhandled.
- **Tabs.** A sync runs under the Web Lock `pedos-sync`, so a browser's tabs take turns, and tells the other tabs what changed on the `pedos-library` BroadcastChannel. Each open tab holds `pedos-open`, shared, so a new tab never clears another tab's Toots.
- **Timeouts.** Vitest's fake timers don't drive `AbortSignal.timeout`, so requests time out through `withinTimeout` (`timeout.ts`), a `setTimeout` the tests can run.
- **Stale builds (#222).** A tab opened before a deploy later loads scripts the server no longer has. Next.js 16 loads a navigation from another build in full, and Turbopack retries a failed chunk once; after that, `stale-build.ts` reloads the page once nothing unsaved is on screen (`holdReload`), at most once in 10 minutes a tab, and never with sessionStorage blocked. A failed `import()` is a `TypeError`: "Importing a module script failed." in WebKit, "Failed to fetch dynamically imported module" in Chromium. A worker fires a plain `error` event when its own script fails, and an `ErrorEvent` when an `importScripts` fails: "NetworkError: Load failed" in WebKit, "Failed to execute 'importScripts'" in Chromium.
- **Installing.** iPadOS Safari says it's a Mac and Chrome on an Android tablet says Linux; only touch gives them away (`install.ts`). An in-app browser built on SFSafariViewController sends Safari's exact user agent, so it can't be told apart. The service worker registers only in a build: on `next dev` it would outlive the session on a localhost port other apps share.

## Shell gotchas

- zsh has `noclobber` set: overwrite a file with `>|`, and use `bash -c` for `set -- $words` loops.
- To call `gh.sh` through a variable, keep only its path in it: `G=~/.claude/skills/serp-github-app/scripts/gh.sh; bash $G pr view <n>`. zsh doesn't word-split `$G`, so `G="bash <path>"; $G ...` fails: zsh looks for one command named `bash <path>`. Writing the whole `bash ~/.claude/skills/serp-github-app/scripts/gh.sh ...` call, as this page does, works too.
