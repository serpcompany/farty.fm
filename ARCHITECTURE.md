# Architecture

The repository's parts, how data moves between them, and the layers the web app keeps. Terms are as [CONTEXT.md](CONTEXT.md) defines them.

## The parts

| Part | What it is |
| --- | --- |
| `apps/web/` | Farty: a Next.js app on Cloudflare Workers, installable from the browser. Each environment has its own Worker, D1 database and R2 bucket ([the web app guide](docs/agents/web.md)). |
| `tools/melody-lab/` | The reference engine, in Python: Recording Analysis, Auto-map and the fart-only renderer, as approved by ear. |
| `fixtures/golden/` | The reference engine's answers for the Fixture Library and the Song Catalog. They are the contract between the reference and the web app. |
| `fixtures/recordings/` | The Fixture Library: real Recordings, with their licenses, for tests and tools. It never ships to Production. |
| `catalog/` | The Song Catalog's cited public-domain scores, imported by `tools/catalog/`. |

## How the web app stays matched to the reference

`tools/melody-lab/export_golden.py` writes the reference's answers to `fixtures/golden/`. The web app's unit tests run its own Recording Analysis and engine on the same Recordings and Songs and compare: Recording Pitch must be bit-identical, which is why `src/lib/analysis/numeric.ts` rounds `exp2` and `log2` as numpy does. `src/lib/catalog/generate.ts` writes the Songs the app ships (`songs.generated.ts`) from the golden copy of each score, so no melody is typed by hand. A change to the reference changes the golden data in the same commit, and the web app follows it.

The renders are checked the other way round: `apps/web/scripts/render-songs.ts [out-dir]` renders every Song through the web engine with the full Fixture Library, into the melody lab's git-ignored output folder by default. For each Song it writes the renderer's exact output as a 32-bit float WAV and its notes as JSON, for `tools/melody-lab/evaluate_renders.py` to measure. It fails when a Song that the golden Arrangement unlocks comes out locked.

## Matching the reference

What the port in `src/lib/analysis/` and `src/lib/engine/` must reproduce, and why. Beside the golden data, `fixtures/golden/files.md` has the contour's smoothing steps and the Recording Pitch estimate, `port-tests.md` how close a port must come, and `planner.md` the planner's ranking and costs, which Auto-map follows term by term.

- **Numerics** (`numeric.ts`): V8's `2 ** x` is one ulp off the C library's `pow` on 43 of pYIN's 519 bins, and `Math.log2` off its `log2` on 3 of the grid's `midi_to_hz` values, so `exp2` (a double-double Taylor series) and `log2` (one Newton step from V8's estimate) are correctly rounded. `pairwiseSum` is `np.sum`, `roundHalfEven` is `np.round`, Auto-map's `pythonSum` is Python 3.12's Neumaier `sum()`, and `compareIds` orders ids by code point, as Python strings do.
- **pYIN** (`pyin.ts`) is librosa 1.0.0's `pyin` (45 to 900 Hz, frame 2048, hop 256, librosa's other defaults), step by step: autocorrelation by FFT with n = 4096 (`next_fast_len(4095)`, each real transform done as a half-size complex one), the cumulative mean normalized difference (librosa zeroes the first energy term), parabolic interpolation, troughs weighted by the Beta(2, 18) threshold prior (for integer shapes, I_x(2, 18) = 1 − (1−x)^19 − 19x(1−x)^18) and Boltzmann prior 2, then one Viterbi step per frame over transitions of probability at least 1e-4. Recording Pitches sit on its 0.1-semitone grid (MIDI x.x259), so its bins, half-to-even rounding and ties must match: a later, longer-period trough overwrites its bin, and the backtrack starts from the first maximum. `evaluate.py` reads renders back up to 1200 Hz instead.
- **Resampling** (`resample.ts`) stands in for soxr's `soxr_hq`, `librosa.load`'s default: a Kaiser-windowed sinc with soxr's figures for that quality (20 bits, 120.4 dB rejection, passband to 1 − 0.05 / TO_3dB(rejection)), cut off midway through the transition band, `ceil(n × 44100 / rate)` samples rounded to float32. An integer rate computes one coefficient table per phase (147 for 48 kHz). It isn't soxr to the bit; the pitch grid absorbs the difference.
- **Audition and the settle time** (`audition.ts`, `variable-resample.ts`) read the gesture back with its pitch held: scipy's `butter`, `filtfilt` (odd extension, `lfilter_zi` state) and numpy's complex division, then Catmull-Rom reads. Only Recording Analysis does this; Songs play farts raw (ADR 0012).
- **The renderer** (`renderer.ts`) is `render()`: `np.linspace` fades, each note's level set over its first 0.25 s, a downbeat where beat ÷ beats per bar is within 1e-6 of a whole bar, and the tanh limiter. Where the reference would fail it keeps the Swift port's behavior, which no golden Song reaches: a note past the end of the mix is clipped, and fades on a note shorter than the fade-in are clamped.
- **Decoding the fixtures** (`apps/web/scripts/decode-audio-file.ts`, which the golden tests and the scripts share) reads the fixtures as libsndfile does: MP3 through mpg123 in gapless mode, so frame counts match exactly, with the channel count from the first frame header (mpg123-decoder doubles a mono stream); WAV scaled by 1/32768; channels averaged in float32.
- **`ANALYSIS_VERSION`** (`version.ts`) goes up whenever Recording Analysis's answers change (2 added the settle time, #116; 3 kept the attack in the contour, #208). An analysis stored with an older version, or none, is analyzed again on the next open (`upgradeAnalyses`). It has its own module so the app reads it without loading Recording Analysis.
- **The Web Workers** share `analysis/worker-requests.ts`: one worker per kind, requests answered by id, and a failed worker rejects what's pending and is replaced on the next request. Recording Analysis is sent a compact copy of the samples, since cloning a view copies its whole buffer, and the render's audio is transferred back.

## How data moves in the web app

1. **Recording:** the microphone feeds an AudioWorklet (`src/lib/audio/`) with the browser's voice processing off. A take is kept only when it heard something: its loudest 50 ms reaches −50 dBFS and stands 4 dB above the take's own room (`heardSomething`), a gate the reference doesn't have. Saving writes the Recording to IndexedDB at once; nothing waits on analysis.
2. **Recording Analysis** runs in a Web Worker (`src/lib/analysis/`) and is kept with the Recording.
3. **Compose and Song Creator:** Pitch Coverage decides which Songs are unlocked. Auto-map chooses the Arrangement, and the renderer plays it with the Recordings, in its own Web Worker (`src/lib/engine/`). A saved result is a Toot.
4. **An account** (free, and needed to keep farts past the visit, ADR 0013) syncs the library: each save, rename and delete waits in an outbox with the change itself, and the sync sends it to the API (`src/app/api/`, `src/server/`), which keeps Recordings and Toots in D1 and their audio in R2. Saving a Toot needs one, and is paid through Stripe Checkout ([Payments](docs/agents/payments.md)).

## Offline: the service worker

`public/sw.js` keeps the app shell so an installed Farty opens offline.

- **Network first.** Every same-origin GET it handles goes to the network, so a deploy shows at once. The kept copy answers only offline, or when a deploy has removed an older build's `/_next/static/` file that a tab opened before the deploy still loads (#222). A build's files never change under the same name.
- **What it keeps:** pages, scripts, styles, fonts and images, only from a whole same-origin 200 (never a redirect, an error or Staging's 401), up to 200 files, oldest first. It never keeps audio (Recordings live in IndexedDB), the Fixture Library (`/fixtures/`, internal only), or the lander's images (`/lander/`, desktop only, #191).
- **The whole shell, ahead of time:** each online load of the start page (`/`), at most every five minutes, fetches the tabs it links to, each Song's page from `/shell.json`, and the scripts they load, including the Web Workers' own chunks. Every tab then opens offline right after install, even one never visited. A load that loses the connection part way tries again on the next start page.
- **Staging's password:** a navigation answered with Staging's 401 unregisters the worker, since a browser won't ask for credentials on a worker's behalf. The next load asks for the password and registers it again.
- **Versions:** the cache is `pedos-shell-v<version>`. Raise `version` when its contents change shape; a new worker deletes every other version's cache when it activates.

## The web app's layout

- `src/lib/analysis/`: Recording Analysis, matched to the reference through `fixtures/golden/`. Plain TypeScript with no DOM or Web Audio, so it runs in the Web Worker (`worker.ts`) and in Vitest alike.
- `src/lib/engine/`: Auto-map and the fart-only renderer, matched to the reference. Plain TypeScript, so it renders in its Web Worker (`worker.ts`) and in Vitest alike. `pnpm exec tsx scripts/render-songs.ts` renders every Song for `tools/melody-lab/evaluate_renders.py`.
- `src/lib/audio/`: the microphone and playback. `recorder.ts` runs a take, `microphone.ts` opens and lets go of the microphone (an AudioWorklet, with the browser's voice processing off), `keep-microphone-open.ts` keeps it open for the launch once Record shows, and `microphone-grant.ts` tracks whether it may open without a tap.
- `src/lib/recording-store.ts`: the `pedos` IndexedDB database, with Recordings (`recording-store.ts`) and Toots (`toot-store.ts`), this browser's working copy. A guest's farts last only the visit (ADR 0013, #237; on 2026-10-28 this replaced #203's rule that a guest keeps their Recordings): each open reads the session, and a guest's new visit clears the last one's Recordings and Toots, except the Recordings the browser held before #237 (`visit.ts`).
- `src/lib/library-sync.ts`, `outbox.ts`, `outbox-send.ts`, `library-pull.ts`, `library-changes.ts`, `library-api.ts`: a signed-in browser's sync with the account (#156). Each save, rename, placement by ear and delete queues in the outbox with the change itself, one entry an item: a delete wins and drops an upload no request has carried, a rename or placement joins a waiting upload, and a Recording waits for its analysis. An op the code doesn't know, from a later build, stays queued and is never sent. The sync reads the account's changes since its last read (`library-pull.ts`), then uploads the outbox (`outbox-send.ts`). A Toot renamed or a Recording placed while its upload was on its way, or one the account already had, is renamed or placed on the account after it; a placement the account refuses is dropped. A Recording this browser already has takes only its Placed Pitch from a read, keeping this browser's own analysis, and a screen's list follows it (`recordingsAfter`). What this browser still has to send wins over what it reads; a full read, once the account's 30 days of tombstones have passed, deletes what it doesn't list; and Recordings not uploaded yet are numbered after the account's. An upload the account refuses as full (409 `limit_reached`, `LIMITS` in `src/server/library.ts`) is marked `accountFull` on its outbox entry, which also drops its `sent`, so deleting it sends nothing; from then this page holds back every upload of that kind, marking each, until there may be room: a delete of that kind the account accepts (204), which lets the same sync try again, a read that deletes one of that kind here, or `claimLibrary` (each open signed in, and each new session). Then it sends the oldest, and holds again if that's refused. The hold lives in memory (`outbox-send.ts`), so it starts empty on each open. Recordings and Toots count the marked entries (`waitingForRoom`, read again on each outbox change), and Sign out tells them apart from farts merely not sent. `pedos.account` names the account the library is, and every library request names it (`x-pedos-library`), so a library never reads from, uploads to or deletes in another.
- `src/lib/account.ts`, `src/components/farty/account-provider.tsx`, `account-step.tsx`: the account from the browser (the sign-in API and `/api/account/`), and the account step after the first Result (#155), with Turnstile on sending a code (`turnstile.tsx`, #237). Every open reads the session, which renews its cookie once a day.
- `src/lib/toot.ts`, `toot-renderer.ts`: a Toot, a Song rendered with the user's Recordings in the render worker, as Song Creator makes it.
- `src/lib/pricing.ts`, `toot-payment.ts`, `src/server/stripe.ts`, `toot-payments.ts`, `src/db/payments.ts`: paying $0.99 to save a Toot (ADR 0010, #204), through Stripe Checkout, or the dev checkout (`/dev/checkout/`) on a local run ([Payments](docs/agents/payments.md)).
- `src/lib/security-headers.ts`: the headers every response carries, which `next.config.ts` sends with pages and `public/_headers` with the static files Production serves without the Worker.
- `src/db/`: the D1 schema (Better Auth's tables, `recordings`, `toots` and `toot_payments`), `createDatabase()` over any D1 binding (`database.ts`, importable from tests) and `getDb()` for a request (`index.ts`, server-only), through Drizzle. Migrations are in `drizzle/`. Better Auth's tables are named after its models and write their own `created_at` and `updated_at`. Times are epoch milliseconds. A Recording's Placed Pitch (`placed_pitch`, ADR 0015) is a column apart from its `analysis`, which keeps the upload's: it changes alone (`PATCH /api/recordings/{id}/`, the last to arrive wins) and outlives each browser's own analysis. The account takes any MIDI note from 0 to 127, wider than the picker, so a later release can widen it; an upload from before #268 has none. A deleted Recording or Toot stays 30 days as a tombstone (`deleted_at`), so other browsers delete their copy; a browser whose last read is older gets the whole library (`full`). Every `updated_at` and `deleted_at` comes from D1's own clock (`d1-clock.ts`), and D1 runs one statement at a time, so a row changed after a library read is never older than that read's `cursor`.
- `src/app/api/`, `src/server/`: a signed-in user's library (Recordings, Toots and their WAVs in R2) and account. Every route outside `api/auth/`, `api/telemetry/` and `api/stripe/webhook/` is built with `userRoute` (`require-user.ts`): session, then `Origin` on writes, `private, no-store`. `every-route.workers.test.ts` fails a route that skips it. Request bodies are read capped (`http.ts`) and checked with zod (`library-input.ts`). WAVs live in R2 at `users/{userId}/{recordings|toots}/{id}.wav`, keyed only by the session's user and a checked id, and each is written once (`If-None-Match: *`). The `workers` tests replace `session-user.ts` with a real `session` row (`test-support/workers-session.ts`); `signed-in.workers.test.ts` signs in for real.
- `src/lib/telemetry/`, `src/app/api/telemetry/`: error reports (`reportError(code, error)`, a stable code and an allowlist, logged by the route), the app's only telemetry, off with Profile's switch or Global Privacy Control (#126). `/dev/telemetry/` sends a synthetic crash and handled error, except in Production.
- `src/server/`: sign-in (#152), server-only behind `auth.ts`: Better Auth email codes (`create-auth.ts`, `auth-request.ts`, `auth-session.ts`), email and the dev mailbox (`email.ts`, `dev-mailbox.ts`, `/dev/mail/`) ([Accounts and sign-in](docs/agents/accounts.md)).
- `src/components/farty/`: the screens, and the app's state in focused providers, which `farty-provider.tsx` nests: Welcome, what plays (`playback-provider.tsx`), the Recordings and their Recording Analysis (`recordings-provider.tsx`), the Toots (`toots-provider.tsx`) and the record flow (`record-flow-provider.tsx`). Each context changes only with what it holds, so a screen re-renders only for the state it reads. `src/components/ui/` is shadcn's, kept as shadcn writes it, less what nothing uses.
- `worker.ts`: the Worker's entry, which answers the host redirects and the Staging gate before Next.js sees a request.

## Layers

Imports point inward, and each rule says what enforces it:

| Rule | Enforced by |
| --- | --- |
| `src/lib` holds the app's logic and never imports components, hooks or routes | Biome's `noRestrictedImports` in `apps/web/biome.json` |
| Components and hooks never import routes (`src/app`) | The same |
| Server code (`src/server`, `src/db/index.ts`) never reaches the browser | `import 'server-only'` in each entry, and Biome keeps `src/lib` from importing `src/server` and `src/db` |
| Server code never imports components, hooks or routes | Biome's `noRestrictedImports` |
| Production code imports no test or test support, and no devDependency | The dependency check (`verify.json`, the `apps/web` part) |
| No import cycles, and every module is reachable from an entry point | The same |
| `src/lib/analysis` and `src/lib/engine` use no DOM or Web Audio, so they run in a Web Worker and in Vitest | Biome's `noRestrictedGlobals` there (`window`, `document`, `navigator`, `localStorage`, `AudioContext`, `OfflineAudioContext`) |
